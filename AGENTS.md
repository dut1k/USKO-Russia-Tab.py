# Правила работы агента

## Проект и приоритеты

Это электронное табло соревнований по карате на PyQt5 и связанная с ним трансляция через локальный сервер FastAPI и браузерный оверлей OBS.
Режимы: кумите, ката по флажкам (отборочные), ката финал (по баллам).
Табло находится в `C:/Users/user/PycharmProjects/USKO-Russia-Tab.py`, сервер — в `C:/Users/user/PycharmProjects/server_USKO-Russia-Tab`.
Основной формат Excel — Пятнова; сохранять поддержку форматов Дементьевой и Юткина.
Главный приоритет: секретарь должен вести соревнования без зависаний и потери результатов независимо от скорости Excel и доступности трансляции.

## Разрешение на изменения

- По умолчанию запрос считается обсуждением или анализом. Разрешены чтение файлов и исследования без изменения рабочих данных.
- Не изменять код без прямого разрешения пользователя в текущем запросе. Перед исправлением объяснить предлагаемое изменение и спросить разрешение, даже если нужно исправить один символ.
- Если пользователь прямо поручил изменить код, дополнительное подтверждение в пределах этой задачи не требуется. Разрешение на одну задачу не распространяется автоматически на следующие.
- Создание или изменение документации и инструкций выполнять в пределах явно порученной задачи. Не считать поручение создать AGENTS.md разрешением исправлять программу.
- SVG и другие готовые изображения изменять только с отдельного прямого разрешения. Разрешение исправить интерфейс или масштабирование не является разрешением менять изображения.

## Простота, комментарии и оптимизация

- Решать конкретную задачу минимальным понятным способом. Не выполнять попутные рефакторинги и не добавлять зависимости или архитектурные слои без необходимости.
- Обязательно писать содержательные комментарии на русском к новой и изменённой нетривиальной логике. Объяснять причины, ограничения, особенности Excel, потоков и порядка сообщений. Не пересказывать очевидный код построчно.
- Поддерживать комментарии в соответствии с кодом.
- Оптимизировать по измерениям. Для Excel отдельно измерять запуск приложения, открытие книги, пересчёт, запись и сохранение; сравнивать до и после на одинаковых сценариях и файлах.

## Интерфейс, потоки и результаты

- Долгие операции Excel и сети не должны блокировать интерфейс, таймер и выбор участников.
- Обращаться к виджетам Qt только из основного потока; передавать результаты фоновой работы через сигналы.
- ФИО, сторона АКА/СИРО, категория, татами и результат должны относиться к одному выступлению.
- Передавать фоновой операции зафиксированные данные выступления. Последующий выбор пары не должен менять уже сохраняемый или отправляемый результат.
- Не терять записи при параллельной работе. При реализации фонового сохранения предусмотреть порядок записей, повторные операции, ошибки и завершение программы с несохранёнными результатами.

## Excel

- Проверять запись только на копиях книг, не изменять исходные протоколы в ходе тестов.
- Сохранять макросы, формулы и оформление XLSM; проверять их сохранность после изменения способа записи.
- Учитывать занятый файл и ошибки сохранения. Сообщать об успехе только после фактического завершения сохранения.
- Не запускать экспериментальные скрипты без проверки побочных эффектов: например, tst.py содержит запись в Excel и не является безопасным набором тестов.

## Трансляция

- Проверять цепочку табло → HTTP → сервер → WebSocket → браузер OBS.
- Учитывать смену пары, сброс и смену победителя, задержанные сообщения, переподключение и перезапуск табло.
- Данные разных татами не должны смешиваться. Недоступность сервера не должна мешать судейству.
- Согласовывать изменения формата сообщений между табло и сервером.

## Телевизионный экран и изображения

- При реализации адаптации учитывать разрешение, соотношение сторон и системное масштабирование Windows. Сохранять читаемость и пропорции, исключать наложения и обрезание значимой информации.
- Учитывать существующий подбор размера шрифта по ширине текста; избегать повторного масштабирования и чрезмерного уменьшения текста.
- Существующие флаги вручную приведены к единому размеру и считаются корректными. Сейчас известной ошибки их отображения нет; исторические сложности не считать текущим багом.
- Флаги отображаются в кругах: обрезание краёв круговой маской нормально и не требует исправления.
- При проблемах с чёткостью исследовать загрузку, масштабирование и отрисовку. Сохранять вектор до отрисовки нужного размера, избегать увеличения маленького растра, учитывать плотность пикселей экрана.
- Любое изменение зрительского экрана проверять визуально на нескольких размерах, длинных ФИО и названиях регионов во всех затронутых режимах. Одного успешного запуска недостаточно.

## Проверки и отчёт

- Для исправленного бага добавлять содержательный регрессионный тест, если поведение можно автоматизировать. Не писать тесты, лишь повторяющие реализацию.
- Проверять затронутую логику и связанные режимы. Для интерфейса, реального Excel и OBS дополнять автоматические проверки ручными сценариями.
- Не запускать проверки, способные перезаписать рабочие книги, отправить данные на используемое татами или вмешаться в соревнование.
- В отчёте указывать причину, изменение, выполненные проверки и ограничения. Явно различать доказанные причины и гипотезы, выполненные и невыполненные проверки.

## Git

- Перед изменениями проверять git status и сохранять незакоммиченные изменения пользователя.
- Группировать изменения по задаче; не выполнять сброс, удаление изменений или переписывание истории без прямого разрешения.
- Commit, push и создание удалённого репозитория выполнять только по прямому указанию пользователя.
- Не включать реальные списки участников и рабочие протоколы в коммиты без согласования.
- У табло и сервера отдельные локальные репозитории; наличие и адрес удалённых репозиториев проверять, не предполагать.
- Не запускать production-деплой без прямой команды пользователя в текущем запросе. Push в ветку с автоматическим деплоем считается деплоем.

Эти правила применяются к обоим проектам. При согласованном изменении общих правил обновлять AGENTS.md в обоих корнях.
